# 能力评估追踪表 — Week 1-2

**评估模型：** 能力导向，通过/未通过（不打分、不评质量）
**使用方式：** D10 课后由教师 + TA 共同填写

## 六项通过条件

| # | 通过条件 | 证据来源 | 判断标准 |
|---|---------|---------|---------|
| 1 | 工作环境可运行 | D2 学生截图 + D9 项目执行 | Claude Code / Claude 桌面 + 工作区挂载正常 |
| 2 | GitHub fork 有 ≥3 个 commit | GitHub 仓库页面 | D3、D4、D5 至少各一个自己名字的 commit |
| 3 | 调用过至少一个 Skill | D5 产物 + explanation 文件 | 产物可见 + SKILL.md 读取记录 |
| 4 | KSTAR 追踪文件完整 | D7 kstar/D7-*.md + D9 kstar/D9-trace-*.md | K/S/T/A/R 五个部分都有内容（不评价质量，只看完整性） |
| 5 | 3D 坐标卡已提交 | coordinate-cards/*.md | 三个轴的自评 + 文字描述都有填写 |
| 6 | 可展示的产物已交付 | D9 产物文件 + D10 展示 | 产物是文件形式，能在 D10 展示中呈现 |

### 这些条件与 Week 3 挑战提交的关系

> Week 1-2 的六项通过条件，每一项都对应 Week 3 起正式挑战的一项基础能力：
>
> - **条件 2（GitHub 提交）→** 六件套提交的基础设施
> - **条件 3（Skill 调用）→** Week 3 使用 elite20-g2-validator.skill 的前置经验
> - **条件 4（KSTAR 追踪）→** 正式 AI 日志（AI_LOG.md）的雏形
> - **条件 5（3D 坐标卡）→** Portfolio 条目中"自我评估"部分的前身
> - **条件 6（产物交付）→** 挑战可复现性要求的最低门槛
