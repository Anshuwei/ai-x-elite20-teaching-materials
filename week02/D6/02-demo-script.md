# Day 6 现场演示脚本 — "10页论文 → 1页备忘录"（完整 K-S-T-A-R 循环）

**时长：** 35分钟 | **方式：** 教师投屏实时操作
**学生任务：** 在 observation-journal 中标注教师的"方向盘动作"

---

## 演示准备（课前）

- [ ] 选一篇 10 页左右的英文经济学工作论文 PDF（推荐 NBER working paper，话题不要太冷门）
- [ ] 把论文 PDF 放入工作区文件夹
- [ ] 确认 Cowork 已挂载该文件夹
- [ ] 准备好 observation-journal 模板（见 03-observation-journal.md），学生人手一份（纸或数字）
- [ ] **排练过至少一次** ☑️

---

## 演示流程

### 阶段 0 — 情境设定（1分钟，边操作边说）

**教师说：**

> "假设我是经济系的一位教授（这不太难 🤔）。我今天早上收到一封邮件，学院让我下午开会讨论一篇工作论文的政策含义。这篇论文 10 页，全英文，我只有 30 分钟准备。这就是我今天要做的——用 AI 帮我把这篇论文变成一页中文备忘录。"

**教师操作：**
1. 在工作区里展示论文 PDF 文件
2. 打开 Cowork 对话界面

---

### 阶段 K — Knowledge（知识准备，3分钟）

**教师说（边想边说，展示思考过程而不是隐藏它）：**

> "在我写任何提示词之前，我需要想清楚几件事——
>
> **我对这篇论文知道什么？**
> - 论文主题是_________（技术性）——它属于劳动经济学领域
> - 研究方法大概是_________（基于面板数据 / DID / IV）
> - 我对这个领域的基本理论框架是了解的（人力资本理论、信号理论等）
>
> **我有什么工具可用？**
> - 我有 pdf Skill 可用——它可以读取 PDF
> - 我应该先让 Agent 读取论文，再要求摘要
>
> **备忘录写给谁？**
> - 学院同事——不是这个领域的专家，但懂经济学
> - 他们需要：核心发现 + 方法可信度 + 政策含义 + 局限
>
> **这步对应 K-S-T-A-R 的 K。K 不是"Agent 知道什么"——是你知道什么。你的 K 决定你能问出多好的问题。**"

---

### 阶段 S — Situation（情境描述，2分钟）

**教师说：**

> "现在我需要把我的情境告诉 Agent。情境包括：为什么需要这个、给谁用、什么格式、什么语气。"

**教师口述提示词草稿（此时不写——先想再说）：**

> "我要告诉 Agent：我有一个 10 页的英文工作论文，我需要它变成一个 1 页中文备忘录。读者是经济学教授但不是这个子领域的专家。他们最关心三件事：这篇论文的核心发现是什么？方法靠谱吗？对我们有什么政策含义？"

---

### 阶段 T — Task（任务工单，5分钟）

**教师边录入边讲解，屏幕上实时可见：**

```
【身份】
你是一位经济学研究助理，擅长阅读英文工作论文并撰写中文政策备忘录。你的读者是经济学教授，但不是该论文子领域的专家。

【输入】
工作区中的 PDF 文件：[论文文件名].pdf

【任务】
先用 pdf skill 阅读全文并提取关键信息，然后撰写一份中文备忘录。

【备忘录结构】（严格按此顺序）
1. 论文信息（标题、作者、年份、NBER编号）
2. 研究问题（一句话）
3. 方法与数据（用什么方法、什么数据、样本量，1-2句）
4. 核心发现（三条，每条配一个关键数字）
5. 政策含义（两句话）
6. 局限与注意事项（一个方法论局限 + 一个外部有效性局限）
7. 结论（一句话，我能直接拿去在会上说）

【格式要求】
- 总字数不超过800字
- 中文撰写
- 备忘录保存为 memo-<论文简称>.md
- 每个部分用 ## 标题分隔
```

**教师的讲解：**

> "注意我刚才做的事：
> 1. 我给 Agent 一个明确的身份
> 2. 我指定了输出的精确结构（7个部分）
> 3. 我给了格式约束（800字，中文，保存为文件）
> 4. 这对应 K-S-T-A-R 的 T——任务规格+验收标准
> 5. **在 IAIV 里，这是 Ask 动作——但我是在做了 Intent 之后才 Ask 的。**"

---

### 阶段 A1 — Action 第一轮（10分钟，可能最长）

**教师执行提示词，Agent 开始处理。**

**在等待时，教师说：**

> "Agent 正在读 PDF、提取信息、组织备忘录。这个过程通常 1-3 分钟。注意：如果你的提示词不够精确，Agent 可能会——
> - 跳过某些部分
> - 编造不存在的数字
> - 把论文的核心发现错误表述
> - 所以我们不能指望第一轮就是完美的。"

**Agent 输出后，教师大声"直播审稿"：**

> "让我们逐部分检查——
>
> ✅ 第1部分（论文信息）：标题、作者、年份都有——检查 ✓
> ✅ 第2部分（研究问题）：一句话说清楚了
> ⚠️ 第3部分（方法与数据）：方法提到了，但**样本量没写**——这是一个问题
> ❌ 第4部分（核心发现）：第三个发现的数据跟论文对不上——**Agent 编造了一个数字**
> ⚠️ 第5部分（政策含义）：太笼统——"政府应关注劳动力市场"这种话等于没说
> ✅ 第6部分（局限）：提到了方法论局限，不错
> ✅ 第7部分（结论）：可以直接用，但需要把编造的数据纠正后再说"

---

### 阶段 A2 — Action 第二轮：迭代（Iterate）（5分钟）

**教师说：**

> "现在我要做 IAIV 中的 I——Iterate。我不会重新写提示词。我在这个对话里直接纠正。"

**教师在同一个对话中回复 Agent：**

```
三个修正，请在备忘录中逐一更新：

1. 第3部分需要补充样本量——论文使用的数据覆盖了多少个观测值？
2. 第4部分第三个发现中，你写的影响幅度是 "-0.032"——请核实论文原文，这个数字在哪个表中出现？如果找不到，标注"需人工核实"并给出论文中最接近的数据。
3. 第5部分政策含义太泛——请根据论文的具体发现，写一句有实质内容的政策建议。如果论文提到了最低工资调整，就写那个；如果提到了教育回报，就写那个。不要写"政府应关注X"这种空话。

更新后的备忘录覆盖原文件。
```

**教师的讲解：**

> "注意我的三个修正指令：
> 1. **具体化**（加样本量）
> 2. **事实核查**（数据是否真实）
> 3. **拒绝空话**（政策建议必须有实质内容）
>
> 这对应 K-S-T-A-R 的第二个 A——Action 不只是一次。好的 Action 总是包括多轮迭代。你可以说我刚才转了三次方向盘。"

---

### 阶段 R — Review（回顾，3分钟）

**Agent 输出修正版后，教师最后审核：**

> "最后一次检查：
>
> [逐项对照验收标准朗读]
>
> - 7个部分齐全？✓
> - 800字以内？✓ （实际 xx 字）
> - 中文撰写？✓
> - 存在工作区？✓
> - 数据经核验？样本量补充了 ✓，第三个发现标注了"需核实" ✓
> - 政策建议有实质内容？✓
>
> **R 不只是检查 Agent 的工作。R 是回头看你自己的 K——经过这一次，你对这篇论文的理解是不是更好了？你对怎么让 Agent 处理经济学论文的经验是不是增加了？这些经验回到你的 K，下次你会写更好的提示词。**
>
> 这就是 K-S-T-A-R 是环形而不是直线的原因——R 不是终点，R 是下一次 K 的燃料。"

---

### 阶段 Close — 交付（2分钟）

**教师说：**

> "文件已经在工作区了。我现在可以直接：
> - 打印出来带进会议室
> - 发给同事提前阅读
> - 把备忘录贴进我们的课程仓库作为示例
>
> 从接收邮件到有备忘录——整个过程实际耗时 25 分钟。其中我的思考（K+S+T）大概 8 分钟，Agent 执行大概 10 分钟，我迭代审核大概 7 分钟。
>
> **注意比例：人思考和判断占总时间的 60% 以上。Vibe Coding 的核心不是让 AI 替你工作——是把你的判断力用在更高杠杆的地方。**"

---

## 给学生的话（演示结束前）

> "你现在看到了一次完整的 K-S-T-A-R 循环。D7 我们会把每个字母拆开仔细讲。D9 你会自己跑一遍。今天你只需要带走一件事：**好的 AI 使用是一系列小决定，不是一次大提示词。**"

## 经济学教授排练备注

| 可能的意外 | 预案 |
|-----------|------|
| Agent 读不出 PDF | 切到手动复制粘贴论文关键段落 |
| Agent 第一次输出就完美 | **反而不利于教学**——这时候要故意挑细节问题，展示"即使看起来好也需要验证" |
| 30分钟不够 | 压缩 Intent 和 Situation 环节——把"想"的过程浓缩成口头表述 |
| Agent 编造了非常逼真的假数据 | **教育时刻**——放慢速度，让学生看清楚你是怎么发现造假的 |
| 论文你不太熟 | 更好——你的 K 不够，这更真实地展示了"即使你不是专家，AI 也能帮你快速进入一个领域" |
