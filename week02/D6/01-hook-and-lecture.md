## 讲义（15分钟）— Vibe Coding 四个动作

### Vibe Coding ≠ Prompt-and-Pray

| Prompt-and-Pray（❌） | Vibe Coding（✅） |
|----------------------|-------------------|
| 写一个提示词 → 看结果 → 如果不好就放弃 | 写提示词 → 看结果 → 判断差在哪里 → 修正 → 再看 → 直到达标 |
| Agent 替你做决定 | 你做决定，Agent 做执行 |
| 没有验收标准，凭感觉判断 | 开始前就知道"做好了是什么样" |
| 外包判断力 | 放大判断力 |

---

### 四个动作 — IAIV（Intent, Ask, Iterate, Verify）

```
Intent          Ask            Iterate         Verify
（意图）   →   （提问）   →   （迭代）    →   （验证）
想清楚要什么    给 Agent 工单    根据输出调整     检查是否达标
  ↑                                                 |
  └──────────── （反馈回 Intent） ←─────────────────┘
```

---

#### 动作 1 — Intent（意图）：提问之前先想清楚

> **"最差的提示词不是写得太短的那个，是写的人自己还不知道要什么的那个。"**

| 需要问自己的问题 | 经济学例子 |
|-----------------|-----------|
| 我需要什么产出？ | 一篇研究简报 vs 一份数据透视表 vs 一张概念图 |
| 谁会用这个产出？ | 我自己（可以潦草）vs 同行（需要专业）vs 学生（需要清楚） |
| 什么样的产出算"好"？ | "学生看完能回答课后题" vs "我能直接放进论文附录" |
| 我有多少时间？ | 10分钟 → 1个提示词；1小时 → 可以迭代3-5轮 |

> **没有 Intent 的 Ask = 让 Agent 猜你要什么 → 你花更多时间修正 → 不如一开始想清楚。**

---

#### 动作 2 — Ask（提问）：开工单

这就是 D4 的四步法提示词。不是新东西——但它现在被放进更大的流程里。

> "四步法是你在一个动作（Ask）里要用的工具。但 Ask 之前有 Intent，之后有 Iterate 和 Verify。"

---

#### 动作 3 — Iterate（迭代）：方向盘，不是重来

这是 Vibe Coding 和 Prompt-and-Pray 的**最大区别**。

| Prompt-and-Pray 的迭代 | Vibe Coding 的迭代 |
|------------------------|-------------------|
| "不行，重新写一个提示词" | "方向对，但第三段需要更具体的例子" |
| 每次都是一次全新的尝试 | 在上一次的基础上调整 |
| 不利用 Agent 已经理解的东西 | 延续对话上下文，节省 token 和时间 |

> **Iterate 不是失败的标志。Iterate 是方向盘。你开车的每一秒都在微调方向盘——没人说你"不会开车"。**

**迭代的三种经典操作：**

| 操作 | 说什么 | 使用场景 |
|------|--------|---------|
| **聚焦** | "很好，但请把 X 部分展开，给具体例子" | Agent 输出太泛 |
| **纠偏** | "你把概念搞反了——不是 X 而是 Y。请重写Z段" | Agent 理解错误 |
| **加约束** | "加上一个表格，对比 A 和 B 在三个维度上的差异" | 输出形状不够 |

---

#### 动作 4 — Verify（验证）：回到验收标准

> **不要因为 Agent 的输出"看起来不错"就接受了。**

| 验证维度 | 怎么验 |
|----------|--------|
| **准确性** | 数据对吗？引文对吗？公式对吗？——Agent 会编造 |
| **完整性** | 我的验收标准里的每一条都满足了吗？ |
| **适用性** | 目标受众能理解吗？能直接使用吗？ |
| **经济学特殊性** | 因果关系方向对吗？内生性讨论到位吗？反事实合理吗？ |

---

### Vibe Coding 的纪律

> "Vibe Coding 不是'感觉对了就行'。Vibe 是一种判断力——你在和 Agent 的对话中，用 Intent 导航，用 Ask 开工单，用 Iterate 转方向盘，用 Verify 踩刹车。每一步都在你的控制之下。"

---

### 和 D4 提示词四步法的关系（一句话说清楚）

> "D4 的四步法教你怎么写好一个提示词（Ask）。今天教的 IAIV 教你怎么跑完一整圈——从想清楚到交付。四步法是一个动作的技术，IAIV 是一场工作流的纪律。"

## 经济学教授备注
- 爵士即兴的类比可以用"凯恩斯 vs 弗里德曼面对通胀数据各自调用不同框架"来经济学化
- IAIV 可以类比为：Intent = 研究设计，Ask = 跑回归，Iterate = 稳健性检验（换个控制变量重跑），Verify = 检查系数符号和显著性能否用理论解释
- Demo 里的经济学任务（论文→备忘录）故意选择了"第一次输出通常不够好"的任务——这样 Iterate 这个动作才能被学生看到
