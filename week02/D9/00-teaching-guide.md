# Day 9 教学指南 — "你的第一个 KSTAR 项目"

**时长：** 60分钟 (Setup 5 + Work Block 50 + Ship 5)
**涉及轨道：** T5 (工作流) + T4 (Skills) + T3 (GitHub)

## 教学目标
- 每对学生完成一个完整的 KSTAR 循环
- **最关键的强制要求：** 在写任何一个提示词之前，必须有书面的 T（接受标准）
- 产出物提交到 GitHub fork，包含 KSTAR 追踪文件
- **预览 Week 3 挑战体系：** G1-G2-G3 三道门和六件套提交的概念

## 教学节奏

| 环节 | 时长 | 教师动作 | 学生动作 |
|------|------|----------|----------|
| Setup | 5 min | 确认选题、搭档分配、分发 KSTAR 跟踪表 | 拿出 D5-weekend 的选题，确认搭档 |
| Work Block | 50 min | 巡视，强制检查 T（不写接受标准不准碰 AI） | 结对编程：K→S→T→A→R |
| Ship | 5 min | 确认提交 + Week 3 挑战体系一句话预告 | commit + push |

## 教师强制干预点

### ⛔ 绝对禁止：没有 T 就开始 A
> **Agents do not prompt until written acceptance criteria exist.**

如果巡视时发现学生已经开始跟 AI 对话但没写下 T：
1. 走过去
2. 问："你的接受标准是什么？写在哪了？"
3. 让他们停下来，先写完 T
4. 再继续 A

### 最常见的 failure mode
学生拿到任务 → 兴奋 → 直接写提示词 → Agent 输出 → 觉得不错 → 没有验证 → 提交。

**这就是 Prompt-and-Pray。你要阻止它。** KSTAR 不是建议——今天是训练纪律。这个纪律在 Week 3 挑战中会变成强制要求——**AI 日志缺失是三条红线之一，提交直接不被接受。**

## 结对规则
- 两人一组：Driver（操作键盘）+ Navigator（读输出、对照接受标准、决定要不要迭代）
- 25分钟后交换角色
- 两个人都要在自己的 fork 上提交——Navigator 用自己的话写 R 部分

## 经济学项目选题池（从 D5-weekend 筛选，确认可行性）

典型的经济学教师/学生可选项目（每个约 50 分钟可完成）：
1. 用 pdf Skill + 四步法，摘要一篇经济学论文并生成教学讨论题
2. 用 xlsx Skill 生成"宏观经济学教学数据可视化"（GDP、CPI、失业率趋势图）
3. 用 docx Skill 生成"经济学课程论文反馈模板"
4. 用 canvas-design Skill 设计"比较优势 vs 绝对优势"教学对比图
5. 用 AI + 四步法写一篇 800 字经济学时事评论（提供数据和选题）

## 关键提醒
- 把接受标准写下来这个动作，是 D9 最重要的学习成果——比产出物本身更重要
- 不要帮学生写提示词——可以问引导问题（"你的 K 里写了什么？""你的验收标准第三条是什么？"），但不给答案
- 如果某对学生 50 分钟内没完成，没关系——D10 展示的不是"完成度"而是"过程"
- **Ship 环节用 1 分钟预告 Week 3：** "D9 的 KSTAR 追踪文件就是未来挑战提交中 AI 日志的雏形。Week 3 起，每个挑战都有正式的 G1-G2-G3 审核——你今天练的就是这个循环的内核。详见项目指南最后的'往前看'部分。"
