## 项目流程（必须在工作块内走完）

### 前 5 分钟 — K + S（写在纸上/文本文件里，不要打开 AI）

```
1. 拿出你 D5-weekend 写的任务方向
2. 打开 kstar/D9-trace-<你的名字>.md，填写 K 和 S 部分
3. 跟你的搭档讨论：你的 K 够吗？S 描述清楚了吗？
```

### 第 5-10 分钟 — T（写接受标准，同样不要打开 AI）

```
1. 填写 T 部分——你具体要产出什么？怎么判断好了？
2. ⛔ STOP：把 T 拿给搭档看。搭档问："如果 Agent 产出 X，你怎么知道它是合格还是不合格？"
3. 如果答不上来——T 不够具体，继续写。
4. 如果答得上来——可以进入 A。
```

### 第 10-35 分钟 — A（执行 + 迭代）

```
Driver: 写提示词，执行，看输出
Navigator: 对照 T 的接受标准逐条检查，决定是否需要迭代

至少做一轮迭代。如果第一轮输出就完美了——
Navigator 的任务是找出一个"还可以更好"的点，让 Driver 练习迭代指令。
```

### 第 35-45 分钟 — R（回顾）

```
1. Driver 和 Navigator 各自写自己的 R 部分
2. 讨论：下次做类似任务时，会在哪里做不同的选择？
```

### 第 45-50 分钟 — Ship（交付）

```
1. 产物文件 + KSTAR 追踪文件都放入仓库
2. git add + git commit + git push
3. Commit message: "D9: [任务简述] — KSTAR完整循环"
```

## 经济学项目选题菜单

### 项目 1 — 论文速读 + 讨论题生成
- **任务：** 给你一篇 8-15 页的经济学 PDF，让 Agent 生成一份"1页摘要 + 3个课堂讨论题"
- **Skill：** pdf
- **验收标准示例：** 摘要 ≤ 500字；讨论题不能是"是/否"题型；每题附参考答案方向（不是完整答案）
- **难度：** ★★☆

### 项目 2 — 宏观数据仪表板
- **任务：** 用 AI 读取宏观经济数据 CSV，生成一份"关键指标一览表" + 一个趋势描述段落
- **Skill：** xlsx（或纯文本处理）
- **验收标准示例：** 包含至少5个指标；每个指标有"当前值+同比变化+趋势判断（↑↓→）"；趋势描述 ≤ 200字
- **难度：** ★★★

### 项目 3 — 教学反馈模板
- **任务：** 生成一份"经济学课程论文评语模板"，包含4类常见问题（论证不完整、数据引用不规范、反事实缺失、政策建议空洞）+ 每类3条可复用的评语
- **Skill：** docx
- **验收标准示例：** 4类×3条=12条评语；每条评语包含"问题描述+改进建议"；语气建设性，不贬低；文件格式正确
- **难度：** ★★☆

### 项目 4 — 经济学概念可视化
- **任务：** 设计一张"通货膨胀的三种类型"教学对比图（需求拉动 / 成本推动 / 预期驱动）
- **Skill：** canvas-design
- **验收标准示例：** 三种类型并列展示；每种类型有"原因→机制→结果"三要素；配色不超过4种；适合投影
- **难度：** ★★☆

### 项目 5 — 经济学时事评论
- **任务：** 给你一组经济数据（CPI、PMI、出口增速等）+ 一篇相关新闻，让 Agent 写一篇800字的经济学评论
- **Skill：** 无需特定 Skill（或 wechat-article-writer）
- **验收标准示例：** 包含至少3个数据引用；有明确的因果推断（不混淆相关与因果）；给出一个政策建议且有约束条件；800±50字
- **难度：** ★★★

## 课堂管理

### 教师巡视路线（按优先级）

1. **先看所有组的 T——** 没写接受标准的立即停下来写
2. **看第一轮输出质量——** 如果有组直接接受了第一轮输出，引导 Navigator 行使职责
3. **看 Navigator 是否参与——** 如果 Navigator 在玩手机，提醒角色互换还剩 X 分钟
4. **时间过半提醒角色互换——** "还有 25 分钟——现在交换 Driver/Navigator"

### 常见干预话术

| 情况 | 教师说 |
|------|--------|
| 学生直接打开了 AI | "你的 K 写好了吗？T 写好了吗？给我看。" |
| 学生的 T 写的是"做一份好的摘要" | "什么叫'好'？你用哪三条标准判断？写下来。" |
| 学生第一轮就满意了 | "很好！现在 Navigator 找出一处可以更好的地方——哪怕只是格式上的。" |
| 学生卡住了，Agent 反复出错 | "回去看你的 K——是不是漏了什么信息没给 Agent？或者你的 T 里某个要求 Agent 在模型中做不到？" |

## 往前看：Week 3 挑战体系预览

> **D9 是你第一次独立跑完 KSTAR 全循环。Week 3 开始，每个挑战都是更大一圈的 KSTAR。区别在于——挑战有正式的"提交-审核-签收"流程。**

### Elite20 挑战的三道门（G1-G2-G3）

```
G1: 方案背书          G2: AI 机械验证       G3: 完成签收
（人审）              （AI 审）             （人审）
≥1 同伴 + ≥1 老师     G2 Agent 自动检查      ≥1 同伴 + ≥1 老师
"这事值得做"          "证据齐全/格式合规"    "承诺的事做到了"
```

### 挑战提交六件套（Week 3 起每个挑战必交）

| # | 文件 | 作用 |
|---|------|------|
| 1 | 方案草案 | 说清"打算做什么、凭什么能做成" |
| 2 | G1 背书 | 同伴 + 老师对方案的书面背书 |
| 3 | 方案设计 | 目标 Level、技术选型、模块分解 |
| 4 | AI 日志 | 全程关键决策节点记录 |
| 5 | 拿来说明 | 复用了什么、License 是什么 |
| 6 | G2 验证报告 | AI Agent 生成的机械验证报告 |

### 你现在就在练最核心的能力

> D9 的 KSTAR 追踪文件，其实就是简化版的 AI 日志。你今天的 T（验收标准），就是未来方案设计的核心。你今天养成的"先读 SKILL.md"习惯，就是你未来读懂 G2 验证报告的基础。
>
> **Week 3 不会更难——因为你现在已经在做一样的事了。只是到时候更正式、更有结构、更有"证据账本"的概念。**
