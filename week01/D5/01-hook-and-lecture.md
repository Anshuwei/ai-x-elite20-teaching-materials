## Hook（5分钟）— "这是什么？"

### 操作
在屏幕上投影一个 SKILL.md 文件的完整内容（选一个已有的，如下例）：

```markdown
---
name: docx
description: 创建、编辑和分析 Word 文档（.docx）。当任务涉及 .docx 文件时触发。
---

## 能力
- 读取 .docx 文件内容（段落、表格、样式）
- 创建新的 .docx 文件
- 修改已有文档
- 提取批注和修订

## 工作流程
1. 使用 python-docx 库解析文档
2. 提取所需内容并返回结构化数据
3. 生成新文档时，先构建内容再写入文件
```

### 互动问答
1. "这是什么？"——让学生猜（代码？说明？配置？）
2. 揭晓："这叫 SKILL.md ——**你用来教 Agent 一个新技能的食谱卡。**"
3. "注意第一行：`name: docx`——当你提到 Word 文件时，Agent 会自动翻出这张卡。`description` 是触发条件。下面是你教它的方法。"

### 一句话过渡
> "Day 2 我们说了墙上有食谱书——今天你亲手翻开一张食谱卡，用它做一道菜。"

## 讲义（15分钟）— Skills 心智模型

### 三个类比，一个原理

#### 类比一：食谱卡 vs 代码

| 代码 | Skill |
|------|-------|
| 需要会编程才能写 | 用自然语言写 |
| 定义了精确的逻辑 | 描述了做事的原则和流程 |
| 改了代码 = 改了功能 | 改了 SKILL.md = 改了 Agent 的行为 |
| 给计算机看 | 给 Agent 看（Agent 把它转译成工具调用）|

> **Skill 不是代码。Skill 是你给 Agent 的"标准操作流程"（SOP）。**

#### 类比二：餐厅后厨的食谱卡

```
墙上挂的食谱卡写的是：
  "宫保鸡丁 → 鸡丁先腌制15分钟，
   花生最后放以保持脆感，
   酱汁比例 2:1:1（酱油:醋:糖）"

不是写"用 C++ 实现鸡丁腌制模块"。
```

SKILL.md 也是如此：**你描述"怎么做"，Agent 负责"执行"。**

#### 类比三：经济学里的"模型手册"

| 经济学 | Skills 系统 |
|--------|------------|
| 你学过 IS-LM 模型 → 看到"央行加息"就会调出 IS-LM 来分析 | Agent 读到 SKILL.md 的 name+description → 看到匹配任务就加载 |
| 你不需要重新推导 IS-LM 每次 | Agent 不需要每次重新想"怎么处理 Word 文件" |
| 好的经济学家有多种模型可用，选对模型是关键 | 好的 Agent 用户有多种 Skills，选对 Skill 是关键 |

### Skill 的工作原理（一张流程图）

```
你的提示词中提到 ".docx 文件"
        ↓
Agent 扫描可用的 SKILL.md 列表
        ↓
匹配 `name: docx` + `description: 当任务涉及 .docx 文件时触发`
        ↓
Agent 加载 SKILL.md 正文作为指令
        ↓
Agent 按照指令描述的方法执行任务
```

### 关键洞察（学生需要理解的三件事）

1. **触发是自动的。** 你不需要说"请使用 docx skill"——Agent 看到 .docx 文件就会自动翻这张卡。
2. **SKILL.md 是透明的。** 你随时可以打开看里面写了什么——这不是黑箱。读了就知道 Agent 会怎么做。
3. **Skill 可以组合。** 一个任务可以触发多个 Skills——就像你做一道菜可能同时用到"切菜"和"调味"两张食谱卡。

---

### Skill 使用的黄金法则

> **用 Skill 之前，先读 SKILL.md。**

原因：
- 你知道 Agent 接下来会怎么做（建立正确的预期）
- 你看到 Skill 的能力边界（知道什么它能做，什么不能）
- 你开始形成"我可以修改这个食谱"的意识（Week 3 你会写自己的）
