## 讲义（20分钟）— 四个类比

### 类比一：仓库（Repository）= 实验笔记本

| 纸质笔记本 | GitHub Repo |
|-----------|-------------|
| 一个课题一本 | 一个项目一个仓库 |
| 封面写课题名 | README.md |
| 里面记所有东西 | 代码、数据、文档都在里面 |
| 放在你桌上 | 托管在 GitHub 云端 |

> **你 fork 的 elite20-starter 就是你这门课的笔记本。**

### 类比二：提交（Commit）= 标日期的一页

| 纸质笔记本 | Git Commit |
|-----------|------------|
| 今天写了3页 | 今天做了3次 commit |
| 每页写了日期 | 每个 commit 有时间戳 |
| 写完签个名 | commit 有 author 信息 |
| 写了什么一看就知道 | commit message 就是"这页我做了什么" |

> **经济学类比：commit 就像你处理面板数据时每一步记录的 do-file 版本——你不会覆盖昨天的 do-file，你会标记每次修改。**

### 类比三：分支（Branch）= "假设……会怎样"

| 场景 | Git Branch |
|------|-----------|
| "我用另一套模型设定跑一遍试试" | 新建一个分支，改动不影响主分支 |
| "如果控制变量换一种测度呢" | 在分支上自由实验 |
| "还是原来的设定好，回到主分支" | 切回 main 分支 |

> **分支是对经济学里"稳健性检验"的天然支持——你可以并行尝试多种设定，不破坏主分析。**

### 类比四：Pull Request = 同行评议

| 学术过程 | GitHub PR |
|----------|-----------|
| 把论文发给同事看 | 打开 Pull Request |
| 同事写批注 | Review comments |
| 修改后再次发出 | Push 新 commit 到同一分支 |
| 接受，发表 | Merge |

> **PR 就是数字化的同行评议——只是比期刊快几个数量级。**
